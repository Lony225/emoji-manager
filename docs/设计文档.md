# 表情包管理器 — 设计文档

## Context

你要一个表情包管理器：有分类和标签，Windows / macOS 优先（Android 后期再加），并且能输入订阅地址同步表情包。
本机有 Node 22、Java 17，没有 Flutter / Rust / Visual Studio，所以选择 **Web 核心 + Electron 桌面壳** 的方案，
业务代码只依赖一个「平台接口」，以后加 Android 只需补一个 Capacitor 实现，不改业务逻辑。


---

## 一、基础功能清单（本期做）

### 1. 表情管理
- 导入图片：按钮选择文件（多选）、整个文件夹、或直接拖拽图片到窗口。支持 png / jpg / gif / webp / bmp / avif / svg
- 自动去重：按内容哈希，重复导入会跳过
- 网格浏览：只显示图片不显示文字名（名字悬停可见），三档大小可调
- 搜索：按名称、标签实时过滤
- 编辑：改名、换分类、改标签
- 收藏：一键收藏，侧栏有「收藏」视图
- 删除：单个或批量，需确认
- 多选：Ctrl/⌘ 点选、Shift 范围选，批量移动分类 / 加标签 / 删除

### 2. 分类
- 新建 / 重命名 / 删除 / 调整顺序
- 每个表情属于一个分类；没分类的在「未分类」
- 删除分类时可选「同时删除里面的表情」或「表情保留到未分类」
- 侧栏显示每个分类的数量

### 3. 标签
- 每个表情可打多个标签，输入时有已有标签联想
- 侧栏标签列表（带数量），点击即筛选；可同时选多个标签
- 全局重命名 / 删除某个标签

### 4. 使用（把表情发出去）
- 点击表情 = 复制到剪贴板，表情上出现「已复制」盖章反馈，直接去微信 / QQ 粘贴
- 复制方式可设：自动（GIF 等动图按「文件」复制保留动画，其他按图片复制）/ 总是文件 / 总是图片
- 右键菜单：复制图片、复制文件、编辑、收藏、移动到分类、删除、在文件夹中显示

### 5. 订阅同步
- 输入订阅地址（指向一个 JSON 清单）即添加并首次同步
- 同步会：下载新表情、更新改动的、按设置删除远端已移除的；每个表情包自动成为一个分类，清单里的标签自动带上
- 你自己加的标签 / 改的名字 / 移动的分类在再次同步时保留
- 订阅管理页：列表、手动同步、全部同步、最近同步时间与错误、删除订阅（可选是否保留表情）
- 启动时自动同步（可关）
- 清单格式（相对地址会按清单位置解析，所以把图片和 JSON 放到任何静态托管即可，如 GitHub Pages / 对象存储）：

```json
{
  "name": "猫猫表情包",
  "description": "可选说明",
  "version": "2026.10",
  "tags": ["猫"],
  "stickers": [
    "images/01.gif",
    { "id": "02", "url": "images/02.png", "name": "开心", "tags": ["开心"] }
  ]
}
```
一个订阅也可以用 `"packs": [ ... ]` 包含多个表情包（每个包一个分类），详见将生成的 docs/subscription-format.md。

### 6. 设置与数据
- 主题：跟随系统 / 浅色 / 深色
- 数据目录可更改（例如放到 OneDrive / iCloud 目录，Windows 和 Mac 之间就能同步同一份表情库）
- 数据格式透明：一个 `library.json` + `stickers/` 图片文件，自动保留上一版备份
- 关闭窗口前自动把未保存的数据写完

### 6.5 桌面浮窗（第二期加入）
- 全局快捷键（默认 `Alt+Shift+E`，设置里按组合键即可改）呼出一个无边框、置顶、不占任务栏的小窗
- 打开即聚焦搜索框；默认显示「最近使用」，没有记录则显示「收藏」，再没有就「全部」
- 输入即在全部表情中搜索；`Enter` 复制键盘焦点项，`↑↓←→` 移动，`Tab` 切换「最近 / 收藏 / 全部 / 各分类」，`Esc` 隐藏
- 未固定：复制后、失去焦点时自动隐藏（启动器模式）；固定后常驻（调色板模式）。固定状态记在浮窗自己的 localStorage
- 浮窗与主窗口是同一个页面的两种角色（主进程用 `additionalArguments` 告知），共用全部组件与 store
- 浮窗只读：从不写 `library.json`，主窗口每次写盘后主进程广播 `library:changed`，浮窗重新读取；避免双写冲突
- 使用记录由主进程维护在 `usage.json`，任一窗口复制后广播给所有窗口；主窗口侧栏也多了「最近使用」视图
- 托盘图标（16–48 px 多套位图，按屏幕缩放比例选用，高分屏不糊；左键打开主窗口，右键菜单：打开主窗口 / 显示隐藏浮窗 / 退出）
- 关闭主窗口最小化到托盘（可关，首次会有气泡提示）+ 开机自启（安装版，带 `--hidden` 只显示托盘；便携版不提供）
- 快捷键注册前做严格校验：Electron 自己的解析很宽松，`NotAKey+Z` 会被注册成全局的 `Z`；被占用时主窗口弹提示，设置里标红
- 窗口位置与大小记在 `window-state.json`，若记住的位置已不在任何屏幕内则回到鼠标所在屏幕右下角

### 6.6 第三期：框选、两级分类、批量复制、命名、导出分享
- 框选：在网格空白处按下拖动画出选框，碰到的表情都被选中；按住 Ctrl / Shift 拖动则在原有选择上追加；拖到边缘自动滚动
- 多级分类（第四期从两级放开）：`Category.parentId`，像文件夹一样任意多级；migrate 只把父不存在 / 指向自己 / 成环的升回一级。
  侧栏按层级缩进、可折叠；查看分类时顶部页签列出它的子分类（没有子分类时列出同级，方便横向切换）
  「全部 | 子 1 | 子 2 | 未分类 | + 子分类」，标题前有可点击的面包屑回到上级；分类视图包含所有子孙分类里的表情
  - 导入文件夹时子文件夹逐级成为子分类；导出的 zip 用 `group` 记完整父路径「一级 / 二级 / …」
  - 拖拽：拖到任意分类中间即成为其子分类，不能放进自己或自己的子孙（成环）；订阅包仍固定在订阅下
  - 新建二级：页签上的「+」、侧栏右键「新建二级分类」；层级移动：右键「放到某个分类下 / 设为一级」
  - 侧栏拖拽（HTML5 DnD，自定义类型不与文件拖入冲突）：行的上 1/4 放前面、下 1/4 放后面、中间 1/4~3/4 放进去（成为二级）；
    拖到一级分类之间即变回一级；列表末尾有「放到这里 → 最后一个一级分类」落点。规则在 `src/ui/categoryDnd.ts`，
    订阅里的表情包分类不能拖离订阅，有二级分类的不能再变二级。`reorderCategory` 只重排受影响的两组同级 order
  - 多包订阅自动变为两级：订阅名是一级（packKey = root），各包是二级；同步时会维护这个结构
  - 删除一级分类连同二级一起删；删除订阅时还有本地表情的分类和它的父分类会保留
- 导入文件夹：系统对话框可一次选多个文件夹（Electron `openDirectory + multiSelections`，主进程只列出图片、渲染进程按需读取；浏览器版只能选一个，多个可一起拖入）
  → 一个弹窗处理全部：每个文件夹一行「分类名（默认文件夹名，可改）」，放置方式三选一：作为一级分类（子文件夹可成二级）/
  放到已有一级分类下成为二级 / 新建一个一级分类放在它下面（多选时默认名取共同上级目录名）。正在查看某分类时默认放到它下面
- 批量复制：多选后「复制 N 个」把多个文件一起放进剪贴板（Windows 用 Set-Clipboard 多路径，macOS 用 AppleScript 文件列表），粘贴即作为多个文件发送；Ctrl+C 对多选同样有效
- 命名：网格里每个表情下方显示名称（设置里可关），点名称 / F2 就地改名；多选「批量命名」生成「名称 1、名称 2…」
- 每个表情下方一行显示「名称 / 分类」（分类只显示最末一级，完整路径在提示里）：「全部 / 最近 / 收藏 / 未分类」视图里显示所在分类；一级分类的「全部」页签里显示二级分类名，
  直接放在一级分类里的标「未分类」；二级分类视图里不显示。点击标签跳到那个分类
- 带二级分类的一级分类，顶部页签末尾固定有一个虚拟的「未分类」页签（视图 `{kind:'category', id, own:true}`）：
  列出直接放在一级分类里的表情。拖进一级分类的图片默认就落在这里，不需要真的建一个“未分类”二级分类
- 在这些视图里拖入 / 粘贴 / 选择散图时，先弹出分类选择（含二级分类、未分类、新建），避免图片默认落到未分类；在某个分类里则直接放进去
- 按内容去重时的“重新导入”：相同图片再次导入且指定了分类 → 把已有的那个移到该分类（保留 id、名字、标签、收藏、使用记录），
  结果里计为 moved；目标是未分类则仍跳过。解决“第一次拖错地方，再拖一次却被当重复跳过”的问题
- 导出 / 导入：任意选中的表情、整个分类、全部表情 → zip（`manifest.json` + `images/`），清单与订阅格式相同，
  分类 → 包、二级分类 → `group`、未分类 → `uncategorized` 包；导入时按名字找或建分类，名称标签原样还原，按内容去重
  - 纯浏览器版下载 zip；桌面版弹保存对话框。拖 zip 进窗口也能导入

### 6.7 预览网站与一键导入（v1.1）
- `site/`：Fastify 服务 + 原生 JS 页面，数据为 `data/index.json` + `data/images/<包>/<内容哈希>.<ext>`（文件名含哈希，可永久缓存、同包去重）
- 公开：`/`（按包分组、搜索、点击复制 PNG、右键下载 / 复制链接）、`/manifest.json` 与 `/packs/<id>/manifest.json`（订阅清单）、`/all.zip` 与 `/packs/<id>.zip`
- 管理 `/admin`：scrypt 口令 + HMAC 签名的 HttpOnly/SameSite=Strict cookie，登录限速；上传（multipart，20 MB/张）、改名改标签、移动删除、导入应用导出的 zip（`group` 并入名字「A / B」）
- 一键导入：页面打开 `emojimanager://subscribe?url=<清单>`；应用在安装器（electron-builder `protocols`）或运行时注册协议，第二实例 / macOS `open-url` 把链接交给主实例，主进程存为待处理，渲染进程取走后弹确认再 `addSubscription`。没装应用时页面 1.5 秒后给出下载与订阅地址
- 部署：`site/deploy/deploy.sh --init` → `/var/www/emoji`、systemd `emoji-site`（用户 emoji，端口 8844）、nginx 站点 `emoji.<域名>`（图片与静态资源由 nginx 直出），HTTPS 由 certbot

### 6.7 第四期：缩略图与动图播放、批量改名、双击折叠
- 缩略图：`Sticker.thumb` 指向 `thumbs/<id>-<时间>.webp`（最长边 192px，动图取第一帧，静态大图缩小；小静态图和 svg 不生成）。
  主窗口 `src/ui/thumbs.ts` 后台生成（并发 2）：网格里正在显示的优先，其余资料变化后 1.5s 空闲扫一遍；删除表情或订阅重新下载时连带删除旧缩略图。
  浮窗只读，直接用已生成的缩略图
- 网格显示规则：静态图有缩略图用缩略图；动图在「播放」时用原图，否则用缩略图（还没生成时退回画第一帧的画布）；悬停总是播放
- `Settings.gridAnimation`：always / auto / hover（旧布尔 `animateInGrid` 迁移：true → auto，false → hover）。auto 在当前视图动图 > 24 张时暂停；筛选条上的播放 / 暂停按钮在 always 与 hover 间切换
- 批量改名：`src/core/rename.ts` 的 `planRename` 纯函数（number / affix / replace / manual），对话框实时预览，`store.renameMany` 一次写入
- 侧栏分类行 `onDoubleClick` 切换折叠（小箭头上的双击忽略）

### 6.8 第五期：粘贴 / 拖入保存、表情制作（加文字）
- 粘贴与拖入统一走 `src/ui/actions.ts` 的 `importLoose`：先同步从 DataTransfer 读出文件、`text/html`、`text/uri-list`、`text/plain`（过了事件就读不到），再按优先级导入——
  真正的文件（有名字的图片 / zip / 文件夹）→ 网页片段 `<img src>`、链接列表、纯文本里的图片地址（http(s) 由主进程 `net:fetchBytes` 下载，不受跨域限制；`data:` 本地解码）→ 最后才用剪贴板位图
  （浏览器把位图包装成刚创建的 `image.png`）。位图和地址同时存在时，只有地址可能是动图（不是 .jpg / .bmp）才去抓原图，抓不到再用位图
- 「粘贴」按钮：桌面端让主进程对本窗口执行 `webContents.paste()`，页面收到的 paste 事件和按 `Ctrl+V` 完全一样（含剪贴板里的文件），所以只有一条处理路径；浏览器版退回 `navigator.clipboard.read()`
- 拖入：窗口级 dragenter / dragover / drop 统一处理（接受 `Files` 或 `text/uri-list`，侧栏自己的分类拖拽用自定义类型不冲突）；侧栏分类行带 `data-drop-category`，落点在哪一行就直接导入到那个分类，
  dragover 时覆盖层显示「松开即导入到“xx”」、该行高亮 `drop-into`；拖文件夹到分类上，导入对话框默认选「放到它下面」
- 表情制作：`src/core/textOverlay.ts` 负责排版与绘制（按换行符分段、超宽逐字折行、上 / 中 / 下 / 自定义锚点、描边 → 填充、阴影、底色），预览层和最终输出调同一个 `drawTextOverlay`，所见即所得；
  字号按图片高度的比例记，描边按字号比例记，换图不用重调
- `src/ui/maker.ts`：读来源（已有表情或刚选的文件），静态图画到画布输出 PNG；动图（GIF / 动态 WebP / APNG，用 `ImageDecoder` 探测帧数 > 1）逐帧解码、叠文字层、`getImageData` 送进
  `src/core/gif.ts` 的 `GifEncoder`，每帧之间让出主线程刷进度，可取消。先扫一遍有没有透明像素：GIF 的透明是 1 位的，帧处理方式要在第一帧定下来
- `src/core/gif.ts` 纯 TypeScript GIF 编码器：每帧单独量化（≤ 256 色直接建调色板，否则中位切分；颜色太多先降到 5 位 / 通道做直方图），LZW 用直接寻址表 + 代号避免清表；
  透明模式每帧全量 + 「恢复背景」；不透明模式只写和上一帧有差异的矩形 + 「保留」；连续相同帧合并停留时间。单元测试里带一个按浏览器规则写的解码器做往返校验
- 入口：表情右键「加文字，做成新表情…」、编辑对话框「加文字…」、导入菜单「选一张图片加文字」；新表情继承来源表情的分类与标签，默认名字取文字第一行

### 6.9 第六期：用模板做表情（meme-generator）
- 引擎：npm 包 `@memecrafters/meme-generator`（napi-rs 原生模块，Skia 渲染，内置 299 个模板）。它的生成调用是同步的，GIF 可能要几秒，
  所以放在 Electron 的 utilityProcess 里跑（`electron/meme-worker.ts`，ESM），主进程 `electron/memes.ts` 管生命周期：按需启动、空闲 5 分钟退出、崩溃后下次请求重启；
  渲染进程通过 `memes:*` IPC 调用，原生崩溃不会带走主进程
- 打包：`scripts/build-electron.mjs` 把各平台的 `.node` 放到 `dist-electron/meme-native/<os>-<arch>/`，`electron-builder.yml` 用 `extraResources` 的 `${os}-${arch}` 宏按目标平台只带一份到 `resources/meme/`；
  工具进程用 `createRequire` 直接加载这个文件，不依赖 node_modules，也绕开了 npm 包自带加载器的两个坑（环境变量分支赋值后没 return、Windows 上本地文件路径多一个斜杠）。
  `package.json` 的 `pnpm.supportedArchitectures` 让 CI 在一台机器上也能装齐 5 个平台的二进制
- 素材：不用模块自带的下载（同步阻塞、没进度），自己按 `resources.json`（jsDelivr 上该版本的清单，带 sha256）下载到 `userData/meme-generator/resources/`：
  字体一次性下载（18 个约 77 MB，首次打开对话框时提示），模板图片按 `key/` 前缀在预览 / 生成前按需下载；生成报 `ImageAssetMissing` 时按路径补下载再试。
  字体只在工具进程启动时扫描一次，所以下载完会重启工具进程。清单缓存 7 天，离线时用旧清单。测试用 `EMOJI_MEME_RESOURCES_ROOT` 指向示例服务器的假清单
- 预览：主进程缓存到 `userData/meme-generator/previews/<版本>/<key>.<ext>`；渲染进程按卡片进入视野的顺序（后进先出、并发 2）去要，滚走了还没轮到的就取消
- 界面 `MemeTemplatesDialog`：左边搜索（关键词 / 标签 / 快捷指令）、类型筛选、标签云、模板网格；右边按模板的 `MemeInfo` 自动生成表单——图片槽（从表情库选或选文件，带名字）、
  文字（必填位空着用模板默认文字）、选项（布尔 / 枚举 / 数字范围），生成结果可直接复制（`copyImageBytes`：动图经主进程写到系统临时目录再按文件复制，启动时清理一天前的）、存为表情（继承当前分类）或另存为文件。`src/core/memeTemplates.ts` 放可测的纯逻辑
- 入口：顶栏「制作」菜单、表情右键「用这张图套模板」（预填第一张图）；浏览器版没有这个能力（`capabilities.memeTemplates`）

### 6.10 第七期：局域网同步（多端增量同步，无需服务器）
- 目标：同一 Wi-Fi / 局域网里的电脑和手机互相同步表情库，不需要填地址、不需要服务器；增量，两边的改动都保留
- 发现：每台设备每 3 秒向各网段的广播地址发一条 UDP（端口 28617，JSON：应用标识、协议版本、设备 id / 名称、系统、版本、HTTP 端口）；
  收到别人的就记为在线并直接回一条让对方立刻看到自己，12 秒没再收到算离线。同一台机器上的两个实例也能互相发现（`reuseAddr`）
- 服务：每台设备内置一个 HTTP 服务（优先 28618，被占用则随机），路径前缀 `/emoji-sync/v1`：
  `POST /pair`（唯一不要令牌的接口）、`POST /begin|/apply|/end|/unpair`、`PUT|GET /file/<文件名>`。除配对外都要 `Authorization: Bearer <令牌>`，令牌和已配对设备一一对应
- 配对：A 向 B 发 `/pair`（带 24 字节随机令牌），B 的屏幕弹出确认并显示配对码（令牌前 4 位，A 的提示里也显示），允许后双方各自记下对方和令牌；之后请求都带令牌。
  身份与配对存在 localStorage（每台设备各自一份，不进资料文件——资料目录可能放在同步盘上被多台电脑共用）
- 合并（`src/core/lan/merge.ts`，纯函数，两边对称）：
  - 同一 id 两边都有：`updatedAt` 更新的整条胜出；相同时按规范化 JSON 定一个确定的胜者。分类因此新增了 `updatedAt`（改名 / 移动 / 排序时更新，旧资料按 `createdAt` 算）
  - 删除记录（墓碑，`library.deleted`）：删表情 / 分类时留下 `{kind,id,at}`；墓碑比记录新 → 两边都删，比记录旧 → 记录复活（删了之后另一边又改过）。180 天后清理
  - 两边各自导入过同一张图（sha256 相同、id 不同）：合并成一条，保留创建更早的 id，元信息取改动更新的一方；另一边把自己那张的文件改名复用，不重传；被合并的 id 记墓碑，第三台设备不会再带回来
  - 父分类不存在 / 成环 → 升为一级，表情的分类不存在 → 未分类
  - 算出“最终样子”后和两边当前状态各做一次 diff，得到各自要做的事；没有差异时不产生任何操作，所以无论谁发起、发起几次结果都一样
- 一次同步（`src/core/lan/session.ts`）：发起方 `begin` 拿到对方的分类 / 表情元信息 / 墓碑 → 本地算合并 → 把对方缺的图片 `PUT` 过去、自己缺的 `GET` 回来（并发 3，失败的那条两边这次都不动）→
  `apply` 让对方应用它那份改动 → 自己应用自己那份。被同步方一次只接受一个会话（5 分钟超时自动解锁），两边同时发起时一方收到 409 后随机退避几秒重试
- 自动同步：已配对设备上线后（id 小的一方先发起，另一方晚几秒发现已同步过就不重复）、本机资料改动 2.5 秒后（缩略图生成等不算）；可在设备对话框里关掉
- 平台层：桌面端 `electron/lan.ts`（`dgram` + `http`，文件直接读写资料目录；请求经 `lan:request` IPC 转交主窗口页面处理）；
  安卓 `LanSyncService.java`（`DatagramSocket` + `ServerSocket` 手写的最小 HTTP，拿 `MulticastLock` 以便收到广播，manifest 开 `usesCleartextTraffic`），经 `EmojiNativePlugin` 的 `lan*` 方法暴露；浏览器版不支持（`capabilities.lanSync`）
- 界面：设置里一个开关 + 「设备…」按钮；设备对话框列出已配对（在线 / 离线、上次同步结果）和在线未配对的设备，配对 / 同步 / 解除配对，本机名称可改；收到配对请求时弹确认

### 6.10 检查更新的国内可达性
- `src/core/update.ts`：`checkForUpdate` 三级回退——GitHub API 直连（12 s）→ 各加速站代理同一个 API 地址（并行 8 s，`firstSuccess` 取最先成功的；实测只有 gh-proxy.com 代理 API）
  → jsDelivr `gh/<repo>@latest/package.json` 拿版本号（`@latest` 解析到最新标签，CDN 缓存 12 小时）+ `@v<版本>/CHANGELOG.md` 取小节当说明，安装包地址按 CI 命名约定拼（GitHub 把附件名里的空格换成点）。
  结果带 `source: 'github' | 'mirror'` 和 `via`
- 加速站名单：内置 `DEFAULT_ACCELERATORS`（2026-10-28 实测 24 个站只有 6 个能代理 165 MB 的安装包），运行时经 jsDelivr 读仓库 `docs/download-mirrors.json` 覆盖（只收 https 前缀、最多 12 个），本次会话只拉一次
- 弹窗 `UpdateDialog`：列出 GitHub 直连和各加速站的下载链接（同一文件加前缀），打开后用各站代理拉该版本的 `package.json` 探测可用性并标 ✓ / ✗；
  版本信息来自镜像时主按钮改走第一个探测通过的加速站，否则直接 GitHub。附件的 SHA-256（API 的 `digest`）放在文件名的提示里，经第三方下载的可以核对
- 没做的：自建镜像（需要服务器带宽）、对象存储 CDN（要云账号和备案）；加速站是第三方服务，本质上要信任它不篡改文件

### 6.11 内置更新（Windows 安装版）
- `electron/updater.ts`：用 electron-updater 的 `NsisUpdater` 只做下载和安装，版本检查仍走 6.10 的三级回退（electron-updater 自己的 GitHub provider 要读 API / atom，国内一样连不上）。
  页面把安装包所在目录的地址交过来（`installerBaseUrl`：GitHub 直连或加上加速站前缀），`setFeedURL({ provider: 'generic', url })` 读该目录下的 `latest.yml`，
  下载完按 yml 里的 sha512 校验，有 GitHub API 给的 SHA-256（`asset.digest`）再核对一次——经第三方加速站下载时只信 GitHub 给的值
- 增量下载：安装程序会把自己存到 `%LOCALAPPDATA%\emoji-manager-updater\installer.exe`，下次只下载 blockmap 里有差异的块；
  `useMultipleRangeRequest: false`（加速站未必支持 multipart Range），失败自动退回完整下载
- 安装：用户点「立即安装并重启」→ 页面先 flush 资料 → `app.quit()` → `quit` 事件里 `updater.install(/S 静默, --force-run)`，
  安装程序等旧进程退出、装到注册表记录的原目录（`--updated` 模式不会重建快捷方式、不删用户数据），装完经资源管理器
  （explorer 的 `ShellExecute`）拉起新版。没点安装只是正常退出时也会顺便装（`updater.install(true, false)`，装完不拉起）；
  改数据目录后的“重启”（`app:relaunch`）这种退出跳过安装，否则安装程序会把刚拉起的进程杀掉。
  装完的自动拉起依赖资源管理器，在没有它的自动化会话里不会发生（真实桌面上正常），所以 `e2e-update-install.mjs` 把“自动重启”
  当提示而非断言，只硬性检查升级成功和数据保留
- 每次下载新建一个 `NsisUpdater`：它会把进行中的 `checkForUpdates` 复用给后来的调用，取消一条线路换另一条时不能被旧的 60 秒超时拖住；
  读 `latest.yml` 这步它不支持取消，用 `Promise.race` 跳出
- 能力判断：`builtinUpdatesAvailable()`（win32 + 打包 + 非便携），经 preload 的 `--emoji-updates=builtin` 参数告诉页面（`capabilities.installUpdates`）；
  便携版、mac、Android、浏览器仍是给链接。测试用 `EMOJI_UPDATE_CONFIG` 指一份 `dev-app-update.yml`
- 打包：`electron-builder.yml` 声明 `publish: github`（只为生成 `latest.yml` / `.blockmap` 和 `resources/app-update.yml`，CI 仍传 `--publish never`），
  Windows / mac 的 `artifactName` 直接写成 `Emoji.Manager-…`：GitHub 会把附件名里的空格换成点，而 `latest.yml` 记的是本地文件名，两者必须一致。
  CI 把 `latest.yml` 和 `.exe.blockmap` 随 Release 一起上传
- 验证：`pnpm e2e:electron` 用伪装的发布目录（`scripts/serve-samples.mjs` 支持单段 Range 和限速）测下载 / 校验失败 / 取消 / 不装了；
  `scripts/e2e-update-install.mjs` 打两个带 E2E 标识的真实安装包装到临时目录，走完静默升级和自动重启

| 层 | 选择 |
|---|---|
| 界面 | React 19 + TypeScript + Vite 8，纯 CSS 变量做主题 |

| 打包 | electron-builder（win: nsis + portable；mac: dmg + zip）+ GitHub Actions |

### 数据模型（library.json）
```
Sticker      id, name, file(stickers/xxx.png), ext, size, categoryId|null, tags[], favorite,
             createdAt, updatedAt, hash(本地导入去重用),
             source: {type:'local'} | {type:'subscription', subscriptionId, packKey, remoteId, url, remoteName, remoteTags[]}
Category     id, name, order, createdAt, updatedAt, [parentId]（子分类才有）, [subscriptionId, packKey, remoteName]（由订阅创建的分类才有）
Tombstone    kind('sticker'|'category'), id, at   ——  library.deleted，删除记录，局域网同步用
Subscription id, url, name, description, lastSyncAt, lastSuccessAt, lastError, stickerCount,
             deleteRemoved(同步时删除远端已移除), autoSync(启动时自动同步)
Settings     theme, gridSize, autoSyncOnStart, gridAnimation, copyMode(auto|file|image), …, lanSync, lanAutoSync
```

### 同步规则
- 表情身份 = 订阅 + 包 + 远端 id（没给 id 就用图片 URL）
- 新的 → 下载；URL 变了 → 重新下载并替换；远端没了 → 按订阅设置删除或保留
- 标签合并：远端标签以新清单为准，你自己加的标签保留
- 名字：你改过的名字保留，没改过则跟随远端
- 分类：每个包对应一个分类，你把表情移到别的分类后不会被同步拉回
- 同时下载 4 个，单个失败不影响整体，错误汇总显示在订阅页
